# Instructor Notes

このメモは、ハンズオンを進行する人向けの補足です。

AIを使えばコード生成は速いため、説明時間は「なぜそう書くのか」「どこに何を書くのか」「エラー時にどこを見るのか」に使う。

## 全体方針

- コードの写経より、構造理解を優先する
- 画像を見せてからコードを見る
- 1つの概念を説明したら、短いコードで対応箇所を確認する
- いきなり全部盛りにしない
- まず本線を理解してから、DTO、Entity、Mapperなどを追加する
- 分からない時に「どこが分からないか」を言えるようにする
- 毎日、最後に確認質問で理解を言語化してもらう

## 説明で特に気をつけること

説明が長くなっても、次の順番を崩さない。

```text
1. 図で見る
2. 日常的な言葉で説明する
3. 専門用語を出す
4. コードで確認する
5. 動かして確認する
```

例えば、いきなり「Service層にビジネスロジックを書きます」と言わない。

先にこう説明する。

```text
Controllerは受付です。
受付は細かい作業を全部自分でやりません。
実際の作業はServiceにお願いします。
Serviceには、登録する、編集する、削除する、というアプリの処理を書きます。
```

## 説明の順番

### Day 1

重視すること:

- フロントエンド、バックエンド、DBの境界
- ReactはDBを直接触らないこと
- APIはReactとSpring Bootの窓口であること
- JSONはデータの受け渡し形式であること

時間をかけるポイント:

- 全体構成図
- HTTPリクエスト / レスポンス図
- 画面操作とAPIの対応

避けたいこと:

- Spring Boot内部の細かい話に入りすぎる
- Reactのhooksを先に説明しすぎる

### Day 2

重視すること:

- Controller、Service、Repositoryの本線
- APIがJSONを返すこと
- 生成されたコードを層ごとに読むこと

説明の順番:

```text
1. ControllerはAPIの入口
2. Serviceは処理を書く場所
3. RepositoryはDBとやり取りする場所
4. まず固定データでAPIを返す
5. API単体でJSONを確認する
```

避けたいこと:

- 最初からDTO、Entity、Mapperを全部説明する
- DB接続の細かい設定で時間を使いすぎる

### Day 3

重視すること:

- DBに保存すると、アプリを再起動してもデータが残ること
- EntityはDBに保存する形
- RepositoryはDB操作
- CRUDとHTTPメソッドの対応

説明の順番:

```text
1. 固定データとDB保存の違い
2. Entityとテーブルの対応
3. RepositoryでCRUD
4. API単体で登録・一覧・詳細・編集・削除を確認
5. フィルタはクエリパラメータで表す
```

避けたいこと:

- SQLやJPAの詳細に入りすぎる
- バリデーションを複雑にしすぎる

### Day 4

重視すること:

- Reactは画面をコンポーネントに分けること
- propsは親から子へ渡すデータ
- stateは画面内で変わるデータ
- 画像URLを `img` タグで表示すること

説明の順番:

```text
1. 画面を部品に分ける
2. RestaurantCardを作る
3. 固定データをカード一覧で表示する
4. フォーム入力をstateで管理する
5. フィルタで表示対象を変える
```

避けたいこと:

- 最初からAPI接続を入れる
- 状態管理ライブラリの話をする

### Day 5

重視すること:

- ReactとSpring BootはAPIでつながること
- APIの結果をstateに入れると画面が変わること
- エラー時はConsole、Network、Spring Bootログを見ること

説明の順番:

```text
1. Spring Boot APIを単体で確認する
2. Reactで固定データ表示を確認する
3. Reactから一覧APIを呼ぶ
4. 登録APIをつなぐ
5. 編集・削除APIをつなぐ
6. フィルタをつなぐ
7. エラー切り分けを練習する
```

避けたいこと:

- 一気に全部つなぐ
- CORSを深掘りしすぎる

## 参加者に問いかける質問

理解確認には、次の質問を使う。

- この画面操作では、どのAPIが呼ばれますか
- このコードはController、Service、Repositoryのどれですか
- このデータはReact、API、DBのどこにありますか
- `imageUrl` は画像ファイルですか、文字列ですか
- APIは成功していますか。どこで確認できますか
- 画面が変わらないとき、まず何を見ますか

## AIを使うときの注意

AIに実装を依頼する場合は、次のように役割を分けて依頼するとよい。

```text
Spring BootでRestaurantのController、Service、Repositoryを作ってください。
まずはDTOとMapperは使わず、基本の流れが分かるシンプルな実装にしてください。
```

次の段階で追加する。

```text
Request DTO、Response DTO、Mapperを追加して、Controllerの入出力をDTOに分けてください。
```

一度に全部依頼すると、コードを追いにくくなる。

## 完成後に説明できるべきこと

最後に説明できるとよい内容:

- グルメ管理アプリの全体構成
- React、Spring Boot、DBの役割
- Controller、Service、Repositoryの役割
- DTO、Entity、Mapperを分ける理由
- CRUD APIのURLとHTTPメソッド
- Reactのprops、state、useEffect
- 画像URLが画面に表示される流れ
- エラーが出たときの確認順序
